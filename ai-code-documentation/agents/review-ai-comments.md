# 審查 AI 註解

## 目標

檢查程式碼庫中疑似由 AI 產生、不必要的解釋性註解。

不要自動移除註解。

## 審查標準

找出符合以下條件的註解：

1. 解釋程式碼明顯在做的事，例如 `// 初始化變數`、`// 回傳結果`。
2. 只是重述函式或變數名稱。
3. 描述直接讀程式碼就能理解的實作細節，或冗長的自然語言說明。
4. 變更歷程（`SKILL.md` 規則 5）：日期戳記、⚠️/✅ 狀態標記、commit hash、「原本/後來/改成/已修正」等敘事、對話或工作階段的引用。
5. 對話式說明，例如「這裡我們…」「如你所要求…」。

以下**不要**列出：

- 安全關鍵註解。
- 硬體限制。
- 協定要求。
- 重要的相容性說明。
- 設計理由、事故教訓等非顯而易見的工程知識（可建議移到 AI_NOTES，但不列為多餘註解）。
- TODO/FIXME 註解。
- 專案慣例要求的 XML 文件註解。

## 輸出

每一則候選註解都要回報：

- 檔案
- 命名空間
- 類別
- 函式
- 行號
- 原因
- 建議

範例：

| 檔案 | 命名空間 | 類別 | 函式 | 行號 | 原因 | 建議 |
| ---- | -------- | ---- | ---- | ---: | ---- | ---- |
| `RobotController.cs` | `Robot.Control` | `RobotController` | `MoveTo` | 42 | 註解只描述方法明顯的行為 | 移除，或移到 `AI_NOTES.md` |

輸出語言依 `SKILL.md` 的「語言設定」決定（預設繁體中文）；英文時欄位改用 `File | Namespace | Class | Function | Line | Reason | Recommendation`。程式碼識別名稱保留原文。

除非開發者明確要求，否則不要修改原始碼。

如果註解含有有意義且非顯而易見的工程知識，建議保留這些知識，並把說明移到 `docs/AI_NOTES.md`（格式依 `SKILL.md` 的「AI_NOTES.md 格式」）。
